# 0005: 一つの管理元と独立したスターター

状態: 初期基盤として採用。確認日: 2026-11-01。

判断記録、英日ドキュメント、契約、スターター、継続更新の仕組みを一つのリポジトリで管理します。各スターターは独立したmanifestとlockfileを持ち、親や隣のソースを参照せずに動作させます。ルートにアプリ共通workspaceは作りません。

出力スクリプトはスターター、契約、ライセンス、生成元を新規ディレクトリにコピーし、生成物とローカル環境設定を除外します。レジストリへの公開やリモートインストーラーは不要です。

Next.js、Expo、Tauriの依存を無理に揃えず、一つのPRで判断と実装を確認できます。クライアントやUIの小さな重複は許容し、契約と共通クライアントの一致、出力後の動作をCIで検証します。

GitHubテンプレートはリポジトリ内容をコピーする機能で、サブディレクトリ選択ではありません。将来用途別のテンプレートrepoを生成する場合も、手動管理する原本を増やしません。

- [GitHubテンプレート](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template)
- [Expoのmonorepoと代償](https://docs.expo.dev/guides/monorepos/)

生成後のアプリは独自の更新周期を持ち、自動で上流変更をマージしません。生成元と移行手順で追跡し、継続した共通更新が必要な箇所だけをパッケージ化します。複数プラットフォームを含むworkspaceは将来追加できる候補です。共通の業務変更や依存更新が繰り返し問題になる場合に再評価します。
